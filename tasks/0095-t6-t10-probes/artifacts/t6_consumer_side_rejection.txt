Attempt: mark the CONSUMER (a compute core using ordinary a.acquire()/a.release())
as the aie_stream wire-only endpoint, i.e. aie_stream=(1, 0) on the input fifo
`fin` in a copy of exp2_probe's design (see t6_probe_in_stream.py, MODE=instream).

Build command (compile-only, --dev npu2):
  python probe_in_stream.py instream <outdir>

Result: control build (MODE=off, ordinary fifo) succeeds. instream build FAILS
at the same aiecc stage that succeeds for the control:

Conclusion: aie_stream is not a transparent flag. The kernel body on the marked
endpoint must be rewritten to use put_ms()/get_ss() (core-issued stream
instructions) instead of ObjectFifo acquire()/release() -- IRON's own verifier
refuses the mismatch outright, at compile time, rather than silently doing
something else.
