# NpuEmbeddings -- the AMD/Xilinx toolchain wheels.
#
# NOT on PyPI. These four come from GitHub release assets, on tags that are
# MUTABLE -- `latest-wheels`, `latest-wheels-no-rtti-2`,
# `latest-air-wheels-no-rtti` and `nightly` all get new assets pushed onto
# them. An asset NAME has never been observed to disappear, but a tag moving is
# what would silently change what you build, so every line is pinned by
# sha256. bootstrap.sh refuses a wheel whose digest does not match.
#
# The dependency chain, verbatim from the wheels' own METADATA, as it was when
# this list still carried four wheels:
#
#   triton-xdna 3.6.0.2026091704+6fc1352        <- REMOVED, see below
#     -> mlir-air[aie]==0.0.1.2026091604+12e6f9f.no.rtti
#        -> mlir_aie_no_rtti==1.4.3.dev55+g10767b5
#        -> llvm-aie
#     -> llvm-aie==22.0.0.2026090201+a36c62b9
#
# triton-xdna is gone, and it was dead weight: it is the Triton-based Python DSL
# for XDNA, and nothing in this tree imports it. Every AIE symbol the exporters
# use -- aie.iron, aie.helpers.taplib, aie.utils, aie.iron.controlflow --
# comes from mlir_aie_no_rtti's own `mlir_aie/python` tree via its aie.pth. The
# one cost was 352 MB of wheel and a download on every bootstrap.
#
# Removing it changed NO other entry, and that is the part worth recording: the
# chain above shows triton-xdna is what PULLS IN mlir-air, so dropping it could
# have left mlir-air installed only as somebody else's dependency. It is not --
# MLIR_AIR_URL below is fetched and installed in its own right, and bootstrap.sh
# installs all three with --no-deps precisely so no wheel's absence can be
# papered over by another one's metadata.
#
# `aie.iron` -- what tools/export/* actually import -- comes from
# mlir_aie_no_rtti's `mlir_aie/python` tree, exposed through its aie.pth.
#
# WARNING: mlir-aie (the RTTI build) and mlir-aie-no-rtti install the SAME
# aie.pth and the SAME mlir_aie/ directory. Installing both makes the last one
# win the payload while BOTH dist-infos remain, which is how this tree ended
# up reporting mlir_aie==1.4.2 while compiling with 1.4.3.dev55. Install one.
# The build here uses no-rtti, because that is what was live.
